# ESP32 connection and serial test

9 November 2026. Procedure only; no hardware pass claimed.

Board: ESP32-S3 DevKitC-style N16R8. Start with no sensors, servo, ESC or battery connected. Goal: verify USB route, firmware upload, boot and binary capture.

| Connection | Connect to | Do not connect |
| --- | --- | --- |
| Laptop USB | Board COM USB-C using a data cable | Native USB connector for this UART0 build |
| ESP 5V and 3V3 headers | Leave unconnected for this first test | Any second supply or ESC 6 V |
| GPIO pins | Leave unconnected | No actuator or sensor required |

## Prepare and upload

1. Place the board on a nonconductive surface. Headers must be properly soldered before later jumper tests. Read COM/USB labels; do not select by left/right appearance in a rotated photo.

2. Plug into COM. Run the commands below. The target is 16 MB flash, OPI PSRAM, QIO, USB CDC disabled, UART0 at 921600 baud.

3. Build the integrated vehicle profile with all calibration/output defaults unchanged. Upload only to the observed port. Close serial monitors before uploading.

```text
arduino-cli board list
python tools/build_firmware.py --vehicle
arduino-cli upload --port COM_NUMBER --fqbn esp32:esp32:esp32s3 --input-dir build/vehicle
```

If build tools are only available in the prepared Ubuntu environment, build there, then use Windows Arduino CLI for the COM upload. A .bin download alone is not a flashing recipe; the input directory must contain the matching exported build files. Do not flash the old N8R2 image.

## Capture and check the result

```text
python tools/capture_serial.py --port COM_NUMBER --seconds 30 --output captures/esp-01
python protocol.py decode captures/esp-01/raw.bin > captures/esp-01/decoded.jsonl
```

1. Use a new directory for each run. No other program may own the port. Capture writes no commands; opening USB may still reset the board.

2. Confirm data, timing, sync and status records exist. With no sensors and default calibration, invalid sensor flags and refusal to arm are expected. Numerical zeros do not mean successful sensing.

3. Press RESET during a second capture. Confirm a new boot identity/report-time restart and resumed packets. Do not interpret sequence wrap alone as reset.

4. After the IMU and encoder are available, repeat for 10 minutes with real data; record report spacing and validity separately from USB arrival batching.

## Pass and troubleshooting

Bench pass: upload succeeds, stable records resume after reset, no unexplained CRC/parser errors or spontaneous resets. A capture beginning/ending mid-frame can have boundary bytes: distinguish them from sustained corruption. Garbled text in a terminal is expected for binary mode. No port: try a known data cable and the COM connector; identify the actual USB bridge before installing its driver. Upload timeout: hold BOOT, tap RESET, release BOOT when download begins, following the board tool guidance.

## Record and send

Send raw.bin, host_reads.jsonl, metadata.json and decoded.jsonl; board photo; firmware commit/profile; port/baud; reset observations. Host read timestamps are chunk timings, not per-packet physical wire times. No safe-driving or physical output pass is established.
