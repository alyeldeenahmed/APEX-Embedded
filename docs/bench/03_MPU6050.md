# MPU6050 connection and measurement test

9 November 2026. Procedure only; no hardware pass claimed.

Use only the ESP32, laptop and MPU breakout. The photos show an MPU-6050-style breakout with regulator components, but do not establish its exact regulator/pull-up circuit. First verify supply and logic levels; then record real stationary and axis data.

| MPU label | ESP32 / connection | Notes |
| --- | --- | --- |
| VCC | 3V3 for initial verified 3.3 V bench supply | Measure sensor rail after regulator. Chip operating rail must be 2.375-3.46 V. If too low, stop and identify regulator; do not blindly switch VCC to 5 V. |
| GND | GND | Common sensor return |
| SDA | GPIO8 | Pull-up only to 3.3 V logic |
| SCL | GPIO9 | Pull-up only to 3.3 V logic |
| INT | GPIO4 | Data-ready timestamp input |
| AD0 | GND | I2C address 0x68 |
| XDA and XCL | Not connected | Auxiliary bus unused |

1. Power off; solder/inspect header joints. Connect GND/VCC first. Check polarity, rail voltage and SDA/SCL idle level before connecting signal wires. Keep leads short. Never expose ESP GPIO to 5 V.

2. Power off and complete the table wiring. Build and upload standalone CSV bench firmware. It does not drive actuators.

3. Record 60 seconds with the board resting still. Wait for ready state; the two-second calibrating flag is a settling marker, not bias calibration.

```text
python tools/build_firmware.py --bench
arduino-cli upload --port COM_NUMBER --fqbn esp32:esp32:esp32s3 --input-dir build/imu-bench
python imu_monitor.py --port COM_NUMBER --seconds 60 --output captures/imu-still-01.csv
```

## Axes noise timing and the first team delivery

1. Check state=4, fault=0, present=1 and fresh valid samples. Acceleration norm near 9-11 m/s2 is a coarse initial screen, not a calibrated acceptance band. Record gyro means and standard deviations; do not subtract the bias before sending raw data.

2. Record six static orientations, each for 10 seconds: +X up, -X up, +Y up, -Y up, +Z up, -Z up. The upward axis should read about +g, downward about -g. Photograph each orientation and label its file.

3. Rotate gently about each positive axis using the right-hand rule. Confirm gyro sign. For the vehicle choose +x forward, +y left, +z up; if the board cannot physically align, define and implement the rotation before setting axes-confirmed. A confirmation flag alone does not rotate data.

4. Record 600 stationary seconds. Inspect invalid samples, duplicate/held source times, resets and read/late/drop counters. Press reset in a separate run and confirm automatic recovery. Power off for wiring changes; do not unplug random live signal wires.

```text
python imu_monitor.py --analyze captures/imu-still-01.csv
python imu_monitor.py --port COM_NUMBER --seconds 600 --output captures/imu-long-01.csv
```

## Interpret timing correctly

Firmware settings: internal 1 kHz, gyro DLPF 42 Hz / accel 44 Hz, gyro +/-1000 deg/s, accel +/-4g; report target 100 Hz. Datasheet filter delays are about 4.8/4.9 ms, not a measured end-to-end delay. Bench summary reports device spacing p50/p99.9/max and sample age p95. For binary pair targets, report counts exceeding 12 ms and 20 ms; these are requested investigation targets, not proof of sensor latency.

## Record and send

Perception: CSV + summary JSON, six-axis photos/sign table, gyro mean/std in rad/s, accel mean/std in m/s2, settings and counters. Integrated imu_valid remains false until mounting/axes are confirmed. Zero bus faults and repeatable signs are the initial go/no-go; measured noise tolerances are for Perception to assess.
